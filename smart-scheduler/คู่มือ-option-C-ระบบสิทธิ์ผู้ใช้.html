ระบบสิทธิ์ผู้ใช้งาน (User Permission System)

SOM SCHEDULE — คู่มือการใช้งานฉบับย่อ · Option C (กำหนดสิทธิ์เองรายคนเต็มรูปแบบ)

ระบบนี้ทำอะไร: เดิมทุกคนใช้ login เดียวร่วมกัน — เห็นทุกเมนู แก้ได้ทุกอย่าง และระบบไม่รู้ว่าใครทำอะไร · ระบบใหม่ให้ พนักงานแต่ละคนมี user ของตัวเอง และ ผู้ดูแลสูงสุด (Super Admin) กำหนดได้ว่าใครเห็นเมนูไหน ทำอะไรได้บ้าง · ทุกการกระทำถูกบันทึกว่า “ใครทำ”

ภาพรวม 3 หน้าจอ

1) หน้า Users — จัดการพนักงาน

สร้าง user, ตั้งรหัส, ปิด/เปิดการใช้งาน, กำหนด Role และติ๊กสิทธิ์รายคน

2) หน้า Roles — สร้างชุดสิทธิ์ (Role)

Role คือ “ชุดสิทธิ์สำเร็จรูป” ตั้งครั้งเดียว เอาไปแปะให้พนักงานได้หลายคน · ติ๊กได้ทั้งระดับเมนู และระดับการกระทำ

เริ่มใช้งาน — 4 ขั้น

  1. เข้าระบบด้วย Super Admin — ผู้ดูแลสูงสุดคนแรก (ตั้งไว้ตอนติดตั้ง) จะเห็นเมนู Users และ Roles เพิ่มมา
  2. สร้าง Role ที่หน้า Roles — เช่น “หน้าร้าน”, “จองอย่างเดียว”, “ดูอย่างเดียว/Support”, “Board” แล้วติ๊กเมนู + การกระทำของแต่ละ Role
  3. สร้าง user ให้พนักงานแต่ละคน ที่หน้า Users — ตั้ง username + รหัส แล้วเลือก Role ให้
  4. เสร็จ — พนักงาน login ด้วย user ตัวเอง เห็นเฉพาะเมนู/ปุ่มที่ได้รับสิทธิ์ · อยากปรับใครก็แก้ Role หรือติ๊กเพิ่มรายคน มีผลทันที

เกร็ดการใช้งาน

• แก้ Role ทีเดียว มีผลกับทุกคนที่ถือ Role นั้น — ไม่ต้องไล่แก้รายคน

• ติ๊กเพิ่มรายคนได้ — บางคนต้องการมากกว่า Role ปกติ ติ๊กเสริมเฉพาะคนนั้นได้ (แสดงเป็น ● ของตัวเอง)

• ปิดพนักงานที่ลาออก — กด “ปิดใช้งาน” แล้วเขา login ไม่ได้ทันที (ข้อมูล/ประวัติยังอยู่ครบ)

• ลบ Role ที่มีคนใช้อยู่ไม่ได้ — ระบบเตือนว่ามีกี่คนถืออยู่ ให้ย้ายคนออกก่อน

• ทุกการกระทำถูกบันทึกชื่อคนทำ — ตรวจย้อนได้ว่าใครแก้/ลบ/จองอะไร
