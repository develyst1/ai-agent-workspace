Your design built as specced; three things are worth reading before the review.

**Separate columns, separate predicate, separate code — one argument.** Dropping is reversible and ending is

**The message is the feature.** `COURSE_DROPPED` reads *"พักอยู่ — กด 'กลับมาเรียน' ก่อน"*. An admin who reads
"cancelled" goes hunting for a mistake; one who reads "paused — resume it first" does the single thing that
unblocks them. There is a test pinning that the string names the way out, because that is the part a later
refactor would flatten.

**Precedence, both boundaries tested rather than argued:** DROPPED above EXPIRED, because telling the owner
"EXPIRED" about a course **he paused himself** sends him to fix something working as designed; below CANCELLED,
because a course paused and then ended **is ended** — the other order would show it as merely paused and offer
a resume button that cannot work.
