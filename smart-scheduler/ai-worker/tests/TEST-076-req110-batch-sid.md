- 🔴 **D10 (HIGH for item 5) — a one-session cover by a coach who is not already on the series cannot be done on screen.**
  - **What happens:** Swap → *เฉพาะคาบนี้* → Save ⇒ **400 `RATE_REQUIRED`** "please enter the covering coach's rate". But the Swap dialog **has no rate box**; the code says so on purpose (*"this door has no rate box"*, `OtherSeriesDialogs.tsx` swap branch).
  - **Why every route is closed:**
    - the server takes the cover rate from `rateMinor` or from the series' own rates (`seriesRateOf`);
    - the series' rates **refuse a coach who is not on it** (`PATCH /other-series/:key {teacherRates}` ⇒ 400 *"อัตราค่าสอนของครูที่ไม่ได้อยู่ในรายการ"*);
    - and the Swap list **only offers coaches not on the row**.
  - **Effect:** for the normal cover case (a different coach steps in), the door always dead-ends. This is exactly Khwan's scenario ("ครู A ไปแทนครู B ครั้งเดียว").
  - The API with `rateMinor` works, so the gap is the missing box.
- 🔴 **D9 (low–medium, contract drift) — the start-date result prints "true" where a count belongs.** After a start-date move the orange box title is **"true คาบต้องยืนยันใหม่"** (expected the number, here 4). The FE types `needsReconfirm: number` (`lib/scheduler/course-start.ts:26`, renders `{n: result.needsReconfirm}` behind `> 0`). The BE returns `plan.needsReconfirm` and uses it as a **truthy flag** (`scheduler.service.ts` ~5197, `...(plan.needsReconfirm ? …)`), so a boolean reaches the screen. The FE test mocks it as `1`, which is why it slipped. The body text is right; only the count is wrong. `I6-2-result.png`.
