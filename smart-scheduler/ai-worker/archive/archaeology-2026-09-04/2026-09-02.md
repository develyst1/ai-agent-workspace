## Product limits

- 🔴 **There is no SMS integration anywhere in this system, and a code delivered into the LINE chat being verified verifies nothing** (the attacker in the accepted-risk scenario is already in that chat). ⇒ **the six digits have no transport**; `deliver2faCode` deliberately **throws** rather than degrading, so the failure lands on whoever flips the switch and not on a family locked out of their children's schedule (BE + SA, 2026-09-02). *(See CONTRADICTIONS — this collides with the existing "one `app_settings` switch away" line.)*
- **There is no audit table anywhere in the product.** The clear-family-LINE-link act is a **log line only**, so "who unbound this family last March" is answerable only as long as logs are kept — and that act is **the only way a LINE account moves between families** (BE, 2026-09-02).
- **A LINE account can belong to only ONE family, and the bot can never unbind it** — the bind is permanent from the bot's side by design; only an admin can clear it (observed, 2026-09-02).
- **Clearing a family's LINE link removes NOTHING but the link** — students, bookings, notes and message history all stay, and the parent may relink at any time. The cleared account is then free to bind to **any** family, including a different one (observed, 2026-09-02).
- **An admin scanning the People LIST cannot see which families are LINE-linked** — link state is deliberately only inside the dialog, because the indicator exists on `GET /parents/:id` and not on `listParents` (deliberate design, ruled 2026-09-02).
- **A child genuinely named `เมนู` cannot be registered through LINE** — words the bot advertises are reserved everywhere; the refusal says so and staff create that student on the People screen instead (SA design call under the owner's order, 2026-09-02).
- **A course has NO teacher column** — the teacher is derived from the course's sessions, and a course is **re-teacherable on purpose** (TASK-140), so one course legitimately carries different teachers across its sessions. A split course therefore names the **next upcoming** session's teacher (observed, 2026-09-02).
- **Only ACTIVE courses are listed to a parent in LINE** — a parent whose course just expired sees nothing at all, with no explanation (observed, 2026-09-02).
