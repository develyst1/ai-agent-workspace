## Unsorted — 2026-08-20/22

- 🔴 **A migration that TIGHTENS a constraint (NOT NULL, CHECK, FK, unique) must not reach an environment before the
  build that satisfies it.** Proven the hard way: `0018_course_subject.sql` applies `SET NOT NULL` only *if no NULL
  rows exist* — `uat`'s course table had just been wiped, so "no NULLs" was trivially true, the constraint applied,
  and **the still-old backend could no longer create a course. The customer reported exactly that.** The gap was
  ~14 hours; deploying the matching code fixed it (Porter, diagnosed and confirmed, 2026-08-20/22).
  ⚠️ *This is the rule the owner declined to put on the board — it survives only in the log.*
- **Second-order lesson from the same incident: the safest-looking state (an empty table) is what made the
  constraint bite.** With real courses present, one underivable row would have left the column nullable and nothing
  would have broken (Porter, 2026-08-20/22).
- 🔴 **DEF-4's shape: a frontend talking to a stale backend crashes the page while nothing in the code is wrong.**
  After any deploy, confirm **both halves** are the new build — `/scheduler/bookings` rendering at all is the
  60-second smoke (Porter, 2026-08-20/22).
- **A fresh machine needs `bun install` in EVERY repo before its first build** — `@mantine/charts` was declared in
  `package.json` but absent from `node_modules` after the owner moved machines, and the build failure looked like a
  code defect (Porter, 2026-08-20/22).
- **A silent drop is a defect class this team names explicitly: with zero recipients the leave notifier wrote
