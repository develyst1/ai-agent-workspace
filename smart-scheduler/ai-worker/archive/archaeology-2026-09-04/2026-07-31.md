## Product limits

- 🔴 **Badges can NEVER carry money.** The frontoffice has **no price field**; revenue lives in the backoffice
  movement ledger, which has **no tag link**. ⇒ **"revenue by branch / onsite vs online" is structurally
  impossible** — which is exactly what *"อยากดูยอด"* implies. **Do not design REQ-014 as if badges could answer
  it** (Porter's read-only audit, 2026-07-31).
- 🔴 **There are TWO independent tagging systems, built twice, sharing nothing:** frontoffice **badges** (on
  bookings) and the backoffice **`bo` tag groups** (on items, from REQ-006). A tag made in one is invisible in the
  other (Porter, 2026-07-31).
- 🔴 **The badge report INNER-JOINS the tag link, so untagged bookings vanish from the totals.** Badges are
  optional and never required, so the untagged pile is large and invisible — the customer would read
  "onsite 40 / online 25" as complete. *"Wrong numbers presented confidently are worse than no numbers"*
  (Porter, 2026-07-31).
- **There is no delete for badge types or values; `deactivate` exists for both and is DEFECTIVE** —
  deactivating a value makes **every booking using it un-editable** (the modal drops it from the picker but still
  submits its id → **400**). ⇒ **the only removal path we have breaks the thing it is used on** (Porter,
  2026-07-31).
- **Badge rename / recolor / reorder are already implemented in the API and validation and have NO UI at all** —
  so **a typo'd badge name is permanent today** (Porter, 2026-07-31).
- 🔴 **`students.parentId` is NULLABLE BY DESIGN.** The schema comment says it outright: *"Nullable for walk-in/
  trial students created before a parent is known; the LINE flow always sets it."* ⇒ **a First-Trial / walk-in
  student can have NO parent at all** — precisely the acquisition cohort the dashboard is meant to measure — so
  with province on the parent, **a naive `student → parent` join silently drops them**. The rule written into
  SPEC-016 and TASK-048: **province-by-student must LEFT-join with an explicit `ไม่ระบุ / unknown` bucket**
  (Sober, 2026-07-31). *If that bucket is large, the business fix is capturing a parent at trial time — not
  relocating the field.*
- 📌 **Same failure mode, two features apart:** the untagged-bookings hole in the badge report and the
  parentless-students hole in the province join are **one class of bug** (Sober naming it, 2026-07-31).

  take HOURS.** Set that expectation up front or the feature will be judged broken (Sober → Porter, 2026-07-31).
- **The parent-link confirmation returns a COUNT of children, never their names** (`พบนักเรียน {n} คนในบัญชีนี้`),
  and returns `""` at zero. ⇒ **a stranger who guesses a phone learns only a number** (built + reviewed
  2026-07-31; the `{names}` string `verify_parent_students` was retired).
- **The one surviving place children's names are interpolated is the post-link "my children" reply**, where the
  parent is resolved from **their own `lineUserId`** — authenticated self-access, not a pre-link reply
  (verified by Sober, 2026-07-31).
- **An AMBIGUOUS teacher nickname binds NOBODY** and replies that staff must complete the pairing; 0 and 1 match
  behave as before, and the session stays retryable. Before this, `rows.find(...)` meant **first match wins**
  (2026-07-31).
- **A LINE flow's session state survives a failed attempt (`AWAIT_CODE` retry path)** — the user can retype or
  send `สมัคร` again rather than being stuck in a loop (2026-07-31).

## Unsorted — 2026-07-31

**Database / migration discipline (the "TASK-042 rule")**
- **Migrations are HAND-AUTHORED and journal-registered; `db:generate` is NOT run** (per `drizzle/README.md`).
  The audit that proves it: **journal entries == `.sql` files, contiguous, no orphans** (applied twice on
  2026-07-31, for `0013`).
- **Agents never apply a migration** — the file is written and registered, and **the human runs `db:migrate`**
  (2026-07-31).
- **Additive-only shape:** `ADD COLUMN IF NOT EXISTS`, and a **partial** unique index (`WHERE col IS NOT NULL`)
  where NULLs must not collide (2026-07-31).

**Environment facts**
- **Thailand is UTC+7 with NO DST** — which is why `.ics` stamps are emitted in UTC (`…Z`) with no `VTIMEZONE`,
  the classic broken-feed cause (Jason's call, ratified by Sober, 2026-07-31).
- **Thai is 3 bytes per character in UTF-8**, so RFC 5545's 75-octet line folding must be counted in **bytes**;
  char-based folding emits over-long lines that stricter clients silently reject (Jason + Sober, 2026-07-31).
- **A deploy can need more than one step, and the middle one is the one that gets missed:** REQ-017 needed
  `db:migrate` **+ set `PUBLIC_CALENDAR_BASE_URL`** (without it the link is relative and useless on a phone)
  **+ restart :4006** (Sober, relayed verbatim by Porter, 2026-07-31).

**Sequencing principle worth keeping**
- **Staging a REQ is a build-order call and belongs to the SA, and it is worth stating why it was or wasn't
  done.** Sober staged REQ-020 (Stage 1 closed a live disclosure with **no staff UI**, so splitting bought real
  safety) and deliberately did **not** stage REQ-019 (the obvious split would have meant **building the same
  parent/student forms twice** and unblocked nobody) — recorded so the contrast is on the record (2026-07-31).
