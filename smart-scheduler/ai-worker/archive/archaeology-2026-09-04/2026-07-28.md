## Unsorted — 2026-07-28

**Architecture facts that outlive any build**
- **"ops" is the RETIRED predecessor of the backoffice.** Party/teacher sync to ops is **obsolete under the local
  `bo.item` model**, not merely deferred — Sober's design call was to **DELETE the ops leg**, not guard it
  (Sober, 2026-07-28). The five teacher-sync call sites and `GET /teachers/reconcile` were removed.
- **The old ops catalog / movement / salary history is NOT carried into `bo`.** Only the freelance budgets are,
  via `public.freelance_budgets`. ⚠️ **Sober flagged this as an assumption for คุณฟีน to confirm and it was never
  answered in this file** — if she ever wants the old ops P&L history in `bo`, that is a separate migration once
  the drift is repaired (Sober, 2026-07-28).
- **`bo.*` tables are owned and migrated by `backoffice-back`.** The scheduling repo must not add migrations for
  them — which is why the freelance-draw idempotency was solved by **deriving held-state from the
  `bo.movement` ledger** instead of adding a unique index (Jason, 2026-07-28).

**Platform quirks**
- 🔴 **Hono matches routes in registration order: a literal path registered AFTER `/teachers/:id` is swallowed as
  an id.** `PATCH /teachers/availability` dispatched to `updateTeacher("availability")` → `where id =
  "availability"` → Postgres **22P02 invalid input syntax for type uuid** → **500 INTERNAL**. `/teachers/type-order`
  had the same latent shadow (observed and fixed, 2026-07-28). **Literal `/teachers/*` routes must stay above
  `/teachers/:id`.**
- **A service-layer test cannot catch a route-dispatch bug.** Jason's DoD test passed because it called
  `setAvailability` directly, bypassing the router; only a **route-level** test (`api.request('/api/teachers/
  availability', {method:'PATCH'})`) would have caught it (Sober, 2026-07-28). Standard adopted that day.
- **A guard that checks a table EXISTS does not prove it is USABLE.** `opsSchemaPresent()` checked only that
  `ops.catalog_items` exists, so a drifted copy (missing `item_group`) passed the guard and then failed the query
  with **42703**, aborting the whole migration including the essential freelance pass (observed, 2026-07-28).
  Fix pattern that shipped: catch `42P01`/`42703` → warn + skip the optional passes → **always run the essential
  pass**; re-throw anything else so real failures are never masked.
- **A 502 from Cloudflare (`origin_bad_gateway`) on `POST /api/teachers/:id/archive` was NOT a missing route** —
  it was the *ops-live* backoffice erroring with `column "item_group" does not exist` (42703) behind it
  (traces captured by the stakeholder, 2026-07-28).
