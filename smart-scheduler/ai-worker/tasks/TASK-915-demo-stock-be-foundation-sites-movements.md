**Reads (CEO + admin — admin-safe, no money):**
- `GET /v1/demo/sites` → the sites.
- `GET /v1/demo/stock?site=&q=` → per-(item,site) balances (item code/name/category + qty).
- `GET /v1/demo/movements?from=&to=&site=&type=&q=&limit=` → the ± history (who/when/from→to/reason), `occurred_on` business date, from/to inclusive ≤366d. No money.

**Writes (CEO + admin; each ONE locked txn, idempotent on a client key, `occurred_on`=the business date, NEGATIVE_BALANCE refusal reusing the shared fn, app error envelope `{error:{code,message,details}}`):**
- `POST /v1/demo/move { key, itemId, fromSiteId, toSiteId, qty, occurredOn? }` — demo site→site (−qty at from, +qty at to; one demo_movement type MOVE with from/to; refuse negative at `from`).
- `POST /v1/demo/from-sale { key, itemId, toSiteId, qty, broken?, reason?, occurredOn? }` — sale→demo: **sale-stock −qty** (a `bo.movement` type → add a new sale-side type `TO_DEMO`, so the 904 movement report shows it) **+ demo +qty** at the site; `broken:true` ⇒ type BROKEN_FROM_SALE with **reason required**. Atomic across both realms; refuse if sale stock would go negative.

- `POST /v1/demo/write-off { key, itemId, siteId, qty, reason, occurredOn? }` — demo −qty, **reason required**; no sale-side change; refuse negative.

**Seed:** parse the Demo tab → `demo_stock` per (item, site); items map to `bo.item` by code (create/attach as 904 does); categories editable later. One-time/idempotent seed script (like 904's rolled-back check pattern), not an API.
