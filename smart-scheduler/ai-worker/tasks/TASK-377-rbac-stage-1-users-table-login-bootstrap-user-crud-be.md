**Bootstrap:** on server start (or the first `/auth/login`?) — ❓ say which is safer for pm2 — if `users` is EMPTY and `BOOTSTRAP_ADMIN_USERNAME/PASSWORD` are set, create that user as super admin (log one line); if the table is not empty the env pair is ignored. **The old `ADMIN_USERNAME/PASSWORD` path is RETIRED** (SPEC-079 §3.1, pending the owner — build it retired; one `if` to keep). `SKIP_AUTH` dev user becomes `{ id: "dev", username: "dev", isSuperAdmin: true }`.

**Guard:** `authMiddleware` verifies the token, then **loads the user row by `sub` (one indexed read), refuses `401` if missing or `disabled_at` set**, and sets `c.get("user") = { id, username, isSuperAdmin, grants: new Set() }` (grants empty until Stage 2). Refusals: `409 USERNAME_TAKEN` (23505 caught in the service, the TASK-364 shape) · `400 PASSWORD_TOO_SHORT` · **`409 LAST_SUPER_ADMIN`** — a super admin cannot disable or demote the last enabled super admin (himself included).

✅ **Decision 1 — the bootstrap runs at the FIRST LOGIN, not at server start — and here is why it is the safer one for pm2.** A start-time hook is a database call at import time: it runs in every `bun test` that imports the root app (the suite never connects), it runs BEFORE `db:migrate` on a box where pm2 restarts ahead of the migration (the table is not there yet — a crash loop or a swallowed error), and it runs on every restart forever. **At login it is lazy and exact:** `POST /auth/login` with the table EMPTY and the pair equal to `BOOTSTRAP_ADMIN_USERNAME/PASSWORD` ⇒ the super admin is created (one log line) and logged in, in one request; the table non-empty ⇒ the env pair is ignored and every login is the table's. Same guarantee (*"only while the table is empty"*), no ordering with pm2, no work on restart, and the break-glass reads exactly as SPEC-079 §3.1 puts it. Pinned: empty + pair ⇒ created; non-empty + pair ⇒ 401; empty + other ⇒ 401, nothing created.
✅ **Decision 2 — the old `ADMIN_USERNAME/PASSWORD` path is RETIRED outright** (built retired, as you said): `auth.ts` no longer reads them; `.env.example` renames the pair to `BOOTSTRAP_ADMIN_*` with the sentence. Pinned by absence.

Two readers depend on it today: the FE session and **`assertMayDiscount` (`discount-plan.ts:147`, `role !== "admin"`)** — the one inline role check in the codebase. Dropping `role` now would make Fern change the session shape twice; it goes when Stage 3 gives her the key.
✅ **Decision 4 — `requireRole` is RETIRED (unused, and `Role` no longer means access); `requireSuperAdmin` replaces it** — the `/users` group's middleware, `403 FORBIDDEN`. Stage 2's `requirePermission(key)` will sit beside it.
