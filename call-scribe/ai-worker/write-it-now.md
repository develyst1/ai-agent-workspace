# Skill — Write it in the same action, not later

**Who needs it:** every role, but it bites the PM hardest — he is the one holding
decisions nobody else can see.
**Costs it has already paid here:** `FAILURES` F-021 (five times in two days) and F-027
(twelve of his own failures recorded in logs and REQs but not in `FAILURES.md`, for two days).

---

## The one line

**"I will record it after this" is the same sentence as "it is not recorded."** Sessions
end mid-thought; the next one inherits only what is in the files.

## Why willpower does not fix it

Nobody in F-021 decided to skip the record. Each time, the decision was made in chat, told
to an SA immediately — *because telling them was urgent* — and the writing was left for a
calmer moment that kept not arriving. **Being helpful and being fast is the whole
mechanism.** A rule that says "remember to write it down" loses to that every time.

The fix is not more discipline, it is **changing what counts as one action.**

## How to do it

🔑 **Bind the write to the telling, not to the end of the session.**

> The approval goes into its home file **in the same action as telling the SA** — not in
> the same session, not in the same hour. One action: write, then send.

If that feels backwards, notice what it buys: the message you send can then be *a pointer
to the record* instead of the content itself, which is what the inbox rule wanted anyway.

**Homes, so there is never a question of where:**

| What you just produced | Where it goes, now |
|---|---|
| a decision or approval of user-facing text | the copy/decision record file |
| a fact about how the system behaves | `SYSTEM-FACTS.md` |
| a defect of your own | `FAILURES.md` — **as an entry, not as a log line** |
| what is in flight / what you are waiting on | the situation file (`RESUME-HERE.md`) |
| what happened | today's log |
| a message to another role | their inbox |

**Writing it somewhere is not writing it.** F-027 is exactly this: twelve failures were
honestly recorded — in logs and REQs — and the file built to collect them stayed empty, so
nobody reviewing failures saw any of them. **A fact in the wrong home is a fact nobody
will find when they need it.**

## The test, before you move on

> **If this session died right now, would the next person know this?**

No → write it before the next sentence you send.

## What this skill is NOT

- Not a reason to write long. One line in the right file beats a paragraph in the wrong one.
- Not a reason to stop and file everything mid-task. **Durable facts and decisions** go
  immediately; narrative goes in the log at the end.
- Not a substitute for telling people. Write **and** send — the file is the record, the
  message is the doorbell.
