**Layout — as TASK-001 §2, plus three small files Sober should know about:**
- `src/lib/validate.ts` — `validate(target, schema)` = `zValidator` with a hook that throws `AppError(400, VALIDATION_ERROR, details = issues)`. Without it zod-validator returns its own body, not our envelope. Every later route uses this.
- `src/lib/time.ts` — `nowIso()`.
- `src/db/migrate.ts` — target of `bun run db:migrate` (opens the client, which applies pending migrations, then prints the tables).
- `drizzle.config.ts` at repo root (drizzle-kit needs it).
- `src/db/client.ts` exports `createDb(path)` + the process singleton `db`; `DATABASE_PATH=:memory:` works (used by `bun test`), which TASK-002's tests need. PRAGMAs: WAL + `foreign_keys = ON`.
- `src/domain/` exists but is empty (TASK-003 fills it).

**One deviation from "generated by drizzle-kit, must match SPEC DDL":** drizzle's sqlite column builder cannot express `COLLATE NOCASE`, so after `bun run db:generate` I renamed the file to `drizzle/0000_init.sql` (journal tag updated) and hand-added `COLLATE NOCASE` to `users.email` (line 95). Every column, CHECK, FK, UNIQUE and index from SPEC-001 §Data Model is present; CHECKs carry names (`users_role_check` etc.) because drizzle requires named checks. Re-running `db:generate` would not re-add the collation — noted in `schema.ts` header. The applied table proves it: `SELECT sql FROM sqlite_master WHERE name='users'` → ``email` text NOT NULL COLLATE NOCASE`. Emails are also lower-cased in code (seed; TASK-002 register).
