# SPEC-002: Sign in with Google
- Source: REQ-002 (also REQ-001 R2 — new user starts `Ordinary`; REQ-004 R3 — admin by email)
- Status: ACTIVE
- Author: Sober (SA), 2026-09-18

## Overview
SPEC-001 §D5 as decided: the FE shows the Google Identity Services (GIS) button; Google hands the
browser an ID token; the FE posts it to the BE; the BE verifies it against `GOOGLE_CLIENT_ID`,
upserts the user, and answers with an httpOnly session cookie. From then on every request carries
the cookie; the FE never sees a token again. Admin = `ADMIN_EMAIL` (= `siegkung@gmail.com`,
SYSTEM-FACTS) compared to the verified email — nothing else.

## API / Interface Design
Base `/api/v1`. All fields camelCase. Error envelope per SPEC-001 §D6.

### `POST /auth/google`
Request body: `{ "idToken": string }` (the `credential` GIS gives the FE).
- 200 `{ "user": User }` + `Set-Cookie: possibility_session=<jwt>; HttpOnly; SameSite=Lax; Path=/; Max-Age=604800` (`Secure` when `NODE_ENV=production`).
- 400 `VALIDATION_FAILED` — missing/empty `idToken`.
- 401 `INVALID_GOOGLE_TOKEN` — signature/audience/expiry check failed (REQ-002 AC-5: no user created).

### `GET /auth/me`
- 200 `{ "user": User }` when the cookie is valid.
- 401 `NOT_SIGNED_IN` otherwise (FE uses this to decide landing vs app; REQ-002 R2, AC-1, AC-4).

### `POST /auth/logout`
- 204, clears the cookie (`Max-Age=0`). Idempotent.

### `User` shape (reused by every later SPEC)
```json
{
  "id": "uuid",
  "email": "a@b.com",
  "displayName": "Name from Google",
  "tier": "Ordinary",
  "isAdmin": false,
  "createdAt": "2026-09-18T15:49:00.000Z"
}
```
`tier` is one of the five exact strings (SPEC-001 §D6). `isAdmin` = `email === ADMIN_EMAIL` (case-insensitive), computed, never stored.

## Data Model
Drizzle `src/db/schema.ts`, migration `drizzle/0000_users.sql` (generated by `db:generate` — drizzle-kit numbers from 0000, applied by Jason per SPEC-001 §D8b):
```sql
CREATE TABLE users (
  id            uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  google_sub    text NOT NULL UNIQUE,          -- Google's stable subject id
  email         text NOT NULL UNIQUE,
  display_name  text NOT NULL,
  tier          text NOT NULL DEFAULT 'Ordinary'
                CHECK (tier IN ('Ordinary','Seeker','Raw Diamond','Visionary','The Possibility')),
  created_at    timestamptz NOT NULL DEFAULT now(),
  updated_at    timestamptz NOT NULL DEFAULT now()
);
```
Existing rows: none (greenfield). Upsert key is `google_sub`; on a returning user, `email`/`display_name` are refreshed from the token, `tier` untouched (REQ-002 AC-3).

## Flow
1. FE landing renders the GIS button (`google.accounts.id.initialize({ client_id: NEXT_PUBLIC_GOOGLE_CLIENT_ID, callback })` + `renderButton`), label per REQ-002 W-1 in the current UI language.
2. Google calls back with `{ credential }` → FE `POST /auth/google { idToken: credential }`.
3. BE: `OAuth2Client.verifyIdToken({ idToken, audience: GOOGLE_CLIENT_ID })` (`google-auth-library`). Failure → 401 (step 3a). Success → payload `sub, email, name` (`email_verified` must be true, else 401).
4. BE upserts by `google_sub`; new row gets `tier = 'Ordinary'` (REQ-001 R2, REQ-002 AC-2).
5. BE signs `{ sub: user.id }` with `SESSION_SECRET` (HS256, exp 7 d), sets the cookie, returns `User`.
6. FE stores `User` in `AuthContext` (from the response, and on every load via `GET /auth/me`), shows name + email + W-2 sign-out in the header.
7. Sign-out: FE `POST /auth/logout`, clears context, routes to landing (REQ-002 AC-4).
8. Guarded pages (idea box and everything personal, REQ-002 R2): if `/auth/me` is 401 → show landing with the button and message W-3 **only when arriving from a cancelled/denied Google flow**, otherwise no message (AC-1 shows just the button, AC-5 shows W-3). *Amended 2026-09-20 (TASK-004 Q-1): GIS exposes no cancel callback for the rendered button, so "cancelled" is detected best-effort (focus returns, no credential within 1.5 s) or from a BE 401. W-3 on a plain first visit is a defect; a missed W-3 after a real cancel is a known limitation.*
9. `requireUser` middleware (BE): reads cookie → verifies JWT → loads user → `c.set('user')`; 401 `NOT_SIGNED_IN` otherwise. `requireAdmin` = `requireUser` + `isAdmin` else **404 `NOT_FOUND`** (REQ-004 R4 wording — never 403, so the admin path is not discoverable).

Edge cases: expired cookie → 401 → FE treats as signed out. Token for a different `aud` → 401. Same Google account twice → one row (unique `google_sub`). Google account without `name` → `display_name = email`.

## Non-functional
- No email/password route exists anywhere (REQ-002 AC-6) — the BE route list is the proof.
- Secrets: `GOOGLE_CLIENT_ID` is public (also in FE env); `SESSION_SECRET` BE-only, ≥ 32 chars, owner-generated.
- Log one line per sign-in: `user.id`, `email`, new|returning. Never log the token.
